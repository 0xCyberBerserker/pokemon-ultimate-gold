# Review guide / Guía de revisión

## English

1. Open the [board](https://github.com/users/0xCyberBerserker/projects/4). The sprint milestone groups the current work; dates stay unset until the game lead confirms them.
2. Read cards in **Revisión**. Each explains what changed, which build was tested, how to try it and known limits. **Bloqueado** names the missing requirement.
3. Comment with **Accepted**, **Changes requested**, or **Blocked**, plus one concrete observation. A reviewer does not need to inspect technical logs.
4. The manager records the decision. A task moves to **Hecho** only when its stated acceptance is met; a technical test may pass while playable acceptance remains open.

Screenshots and short demonstrations can support review without giving access to personal saves. The project owner manages collaborator access in GitHub settings.

If Projects is unavailable, review the milestone issues and their status labels instead. The manager must keep these labels consistent with the board whenever Projects is available.

## Español

1. Abre el [tablero](https://github.com/users/0xCyberBerserker/projects/4). El hito del sprint agrupa el trabajo actual; las fechas se fijan cuando las confirme el responsable técnico.
2. Mira **Revisión**. Cada tarjeta explica qué cambió, qué versión se probó, cómo comprobarlo y qué falta. **Bloqueado** explica qué impide avanzar.
3. Comenta **Aceptado**, **Necesita cambios** o **Bloqueado**, con una observación concreta. No hace falta leer logs técnicos.
4. El gestor registra la decisión. Una tarea pasa a **Hecho** cuando cumple su criterio; una prueba técnica puede pasar mientras sigue pendiente la revisión jugable.

Las capturas y demostraciones breves ayudan a revisar sin compartir partidas personales. El propietario gestiona el acceso de colaboradores en la configuración de GitHub.

Si Projects no carga, revisa las issues del hito y sus etiquetas de estado. El gestor mantendrá esas etiquetas coherentes con el tablero cuando esté disponible.
